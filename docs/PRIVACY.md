# Privacy behavior and release status

This file describes the current local implementation. The app and its Pages site have not been published; it is not a substitute for a reviewed public privacy notice.

## Current behavior

- No account or behavioral analytics are implemented. The app contains no advertising.
- Location permission is requested only when the user chooses location in the permission flow or taps the map location control. The resulting fix is held in app memory and used locally to sort/filter pharmacy records and recenter the map.
- The map loads OpenFreeMap tiles over the internet. Tile requests disclose the visible viewport to the tile provider; the privacy page in the app explains this.
- Pharmacy packs, favorites, and preferences are stored on the device. On Android the pharmacy pack uses SQLite; the browser fallback is memory-only.
- Selecting a pharmacy's call action opens the device dialer. Selecting route opens the pharmacy destination in a compatible maps app. Locapharm does not send a route request or GPS start point to a routing service.
- Pharmacy corrections and bug feedback are unavailable unless their remote feature flags are enabled; both are off by default. A correction includes the pharmacy ID and selected reasons, with optional free text encrypted before storage for at most 30 days. Reporter GPS is not sent, and contact details are not collected by the app form. Bug messages are encrypted and retained for at most 30 days; basic diagnostics are sent only after opt-in and are allowlisted to app version, platform, language, coarse network state, and a fixed error code. The random installation UUID is used for rate limiting and stored only as an HMAC; it is not a hardware identifier. Worker report/vote/config/feedback endpoints, the D1 migration, and opt-in digest workflow are authored but have no database binding, production deployment, or public privacy review. GitHub Actions embeds the public Worker origin into app builds. `/config` reads emergency contacts from the same sourced `data/emergency.json` file; the emergency screen keeps that file as an offline fallback. The Worker can accept optional proposed pharmacy coordinates for reports, but the app currently does not collect them; those coordinates must describe the pharmacy and never the reporter's GPS fix. Free-text report details and optional contact numbers are encrypted before storage; contact requires explicit consent. Reports, feedback, and votes expire after 30 days. Protected API responses redact phone- and email-like text; the GitHub issue digest excludes free text and contacts entirely. Votes are one per installation/pharmacy/duty window, and never change a pharmacy status. Rate-limit identifiers are HMACs of the installation ID and Cloudflare client IP, with IP buckets purged after 24 hours. Notifications, speech, and in-app turn-by-turn navigation are not implemented.

## Before public release

Review the public notice against the final map provider, report and feedback behavior, the Android permission manifest, and applicable Cameroon requirements before enabling submissions. Recheck the provider's terms and the MINAT emergency contact source. The Worker retention and encryption behavior is implemented in source but has not been deployed or independently verified.
